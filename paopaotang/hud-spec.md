# 泡泡糖 · HUD 规格

> 原则:HUD 上每个元素都能在 ux-flow.md 里指到"玩家在哪一拍真的看它"。指不到的不进这份规格。
> 这份是给 Forge(cc-coder)落成 **DOM overlay** 的施工图,不是引擎内世界坐标 UI——HUD 全部是叠在渲染画布上的 HTML 层,状态来源全部读 `world` 里的游戏状态(见每项"状态来源")。
> 布局:顶部一条状态栏(左资源 / 中得分 / 右敌人),横幅走屏幕居中层。移动端预留,但 v1 只做桌面。

## 全局布局(ASCII 线框)

```
┌───────────────────────────────────────────────────────────┐
│ 💧1/1  🔥1  👟4.0            SCORE 0            👾×3        │  ← 顶部状态栏 (.hud-top)
│                                                             │
│                                                             │
│                         [ 游 戏 画 面 ]                      │
│                                                             │
│                                                             │
│                  ╔═══════════════════════╗                  │
│                  ║   胜利 / 失败 横幅      ║   ← 居中层 (.hud-banner)
│                  ╚═══════════════════════╝                  │
│                     按 R 重来  (延迟浮现)                    │
└───────────────────────────────────────────────────────────┘
底部教学提示条 (.hud-hint) 仅前 10 秒出现,之后销毁
```

## 一、常驻状态栏元素(顶部 `.hud-top`)

### 1. 泡泡数量 💧(最高优先级——玩家每次放泡前都看)

| DOM 结构 | 状态来源 | 何时显示 + 动效 |
|---|---|---|
| `<span class="hud-bubble">💧 <b data-avail>1</b>/<b data-cap>1</b></span>` | 可用数 = `泡泡上限 - 当前在场我方泡泡数`;上限来自玩家 `BubbleCap` 组件(初始 1,吃💧 +1 上限 5) | **常驻**。放泡瞬间可用数 -1,数字变灰(`.spent`);泡泡爆掉回收后 +1,数字弹回亮色并 scale 1→1.2→1 弹一下。上限 +1 时整块闪白 0.3s。可用为 0 时轻微变暗提示"放不了了" |

### 2. 爆炸范围 / 火力 🔥

| DOM 结构 | 状态来源 | 何时显示 + 动效 |
|---|---|---|
| `<span class="hud-fire">🔥 <b>1</b></span>` | 玩家 `FirePower` 组件,初始 1,吃🔥 +1,上限 6 | **常驻**。吃🔥 升级时数字 `n→n+1` 高亮跳动 1s(黄闪+上跳 4px),提示"下一颗炸得更长"。这是柱3 变强的即时确认,也是柱1 自炸风险上升的预警锚点 |

### 3. 移动速度 👟(低频——默认弱显示,仅升级瞬间抢注意力)

| DOM 结构 | 状态来源 | 何时显示 + 动效 |
|---|---|---|
| `<span class="hud-speed">👟 <b>4.0</b></span>` | 玩家 `MoveSpeed` 组件,初始 4.0,吃👟 +0.6,上限 6.4 | **常驻但默认 60% 透明度**(玩家平时不盯它)。吃👟 时数字更新 + 全亮高亮跳动 1.5s 再淡回。存在理由:节拍表 30–40s 玩家踩到👟需要一个"我变快了"的确认;平时不该占视觉 |

> 自检:👟 是三个资源里最不常被看的,一度想删。保留理由=踩鞋子那一拍没有反馈玩家会问"这鞋子干嘛的";解法是**平时压暗、升级瞬间才亮**,而不是删。

### 4. 得分 SCORE(中央)

| DOM 结构 | 状态来源 | 何时显示 + 动效 |
|---|---|---|
| `<span class="hud-score">SCORE <b>0</b></span>` | `Score` 资源(全局)。炸方块 +10、击杀敌人 +100、踩道具 +5(数值待 Iori 确认,先占位) | **常驻**。加分时数字滚动到新值 + 在世界坐标事件点(方块/敌人处)另飘一个 `+10`/`+100` 跳字(独立于 HUD,`.score-popup` 生成后 0.8s 上浮淡出)。得分是柱1/柱3 成功的即时糖 |

### 5. 剩余敌人 👾(右侧——胜利条件的进度条)

| DOM 结构 | 状态来源 | 何时显示 + 动效 |
|---|---|---|
| `<span class="hud-enemies">👾 ×<b>3</b></span>` | 存活敌人计数(遍历带 `Enemy` 标记的实体);初始 3,元进度台阶可 3→4→5 | **常驻**。击杀 -1 时数字 `×n→×n-1` 红闪一下 + 抖动,给"清掉一个"的确认。降到 `×1` 时数字持续微脉冲(提示"最后一个,快赢了")。这是唯一的胜利进度信号 |

## 二、教学提示条(`.hud-hint`,仅前 10 秒)

| DOM 结构 | 状态来源 | 何时显示 + 动效 |
|---|---|---|
| `<div class="hud-hint">方向键移动</div>`,内容随进度替换 | onboarding 状态机(见 onboarding.md):`未移动` → 显"方向键移动";`已移动·未放泡` → 换"空格键放泡泡";`已放第一颗泡` → 淡出并销毁 | 底部居中淡入。玩家做出对应动作后 0.5s 淡出下一条。**放完第一颗泡后整条永久移除**,不再占屏。绝不写"按 X 跳跃"式命令,只在玩家将要需要它的前一刻给 |

## 三、胜利 / 失败横幅(`.hud-banner`,居中层)

### 失败横幅

| DOM 结构 | 状态来源 | 何时显示 + 动效(节奏) |
|---|---|---|
| `<div class="hud-banner lose"><h1>被泡泡困住了</h1><p class="retry">按 R 重来</p></div>` | 我方被水花命中 → `GameState = 'lose'` | 死亡定格 **0.6s**(不弹横幅,让玩家看清怎么死的)→ 画面压暗 0.3s → 横幅从上落下并轻微回弹 → **再隔 0.5s**「按 R 重来」才淡入并持续脉冲(0.9 → 1.0 透明度循环)。全程约 1.4s,给情绪一个空拍,不催 |

### 胜利横幅

| DOM 结构 | 状态来源 | 何时显示 + 动效(节奏) |
|---|---|---|
| `<div class="hud-banner win"><h1>全场清空!</h1><p class="score-final">SCORE 1240</p><p class="retry">按 R 再来一局</p></div>` | 剩余敌人 = 0 → `GameState = 'win'` | 最后一个敌人击杀反馈播完 0.8s → 全屏彩色泡泡上浮庆祝 0.5s → 横幅弹入(scale 0.8→1 带弹性)→ 最终得分从当前值滚动累加一遍(仪式感)→ 「按 R 再来一局」1.0s 后浮现脉冲 |

### 「按 R 重来」文案 + 节奏规则

- **文案**:失败=「按 R 重来」;胜利=「按 R 再来一局」(赢了要引导"再赢一次",别用"重来"这种含失败暗示的词)。
- **出现节奏**:一律**晚于横幅主标题 0.5–1.0s** 才浮现——先让玩家消化结果,再给出口。立刻并排出现会显得"催你快滚"。
- **动效**:浮现后持续 `opacity 0.9↔1.0` 慢脉冲(约 1.2s 一循环),暗示"这里可交互、在等你"。
- **响应**:按 R 立即重开(无二次确认弹窗,小游戏要快)。可选:横幅上追加一行极小字「Esc 返回」若有菜单。
- **防误触**:横幅落定前的那 0.5s 内按 R 无效(避免玩家死时正巧按着键秒跳过没看清)。

## 四、残局警示(非 HUD 元素,但归 Forge 落地)

- 软方块 <30% 触发残局:屏幕**四边泛红径向脉冲**(`.hud-endgame-vignette`,CSS radial-gradient 边缘,呼吸 1.5s 循环),不加任何文字。这是"节奏变快了"的唯一提示,靠体感不靠读字。

## 给 Forge 的落地约定

1. HUD 全是画布之上的 DOM overlay 层,`pointer-events: none`(除非将来加可点按钮),不拦截游戏输入。
2. 所有数字元素都从 `world` 的组件/资源单向读取渲染,HUD **不持有游戏状态**,只做展示。
3. 状态来源里标"待 Iori 确认"的得分数值先用占位常量,别自己拍板。
4. `.score-popup` 世界坐标跳字需要把实体世界坐标投影到屏幕坐标——若 v1 成本高,可降级为在 HUD 得分处直接滚动,跳字延后。
5. 动效时长(定格 0.6s / 横幅延迟 0.5s 等)全部抽成常量,方便手感联调时改。
