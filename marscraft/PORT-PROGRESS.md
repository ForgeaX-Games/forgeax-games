## Per-tick protocol (the cron follows this exactly)

0. Read `ENGINE-API-CHEATSHEET.md` (same dir) for the forgeax API — don't re-derive it.
   Do foreground work only (no `run_in_background`) so ticks stay serialized.
1. Read this file. Find the **first** milestone whose checkbox is unchecked.
2. Pick its **next unchecked task**. Do a real, complete implementation (port the
   actual source logic; no placeholders, no `// TODO later`).
3. Translate Three.js render calls → forgeax ECS (`MeshFilter`/`MeshRenderer`,
   procedural geometry via `createXGeometry`/`meshFromInterleaved` +
   `world.allocSharedRef('MeshAsset', …)`, `Transform`, lights). Keep the
   source's ECS/game logic (components → `defineComponent`, systems →
   `world.addSystem`).
4. Verify: `bun run typecheck` (or tsc on the game) must pass; then a Playwright
   smoke against `http://localhost:15173/preview/?game=marscraft` — no console
   errors, entity count > floor, fps > 0 (start the stack if down; see Verify).
5. Commit in the `packages/games` submodule with a milestone-scoped message.
6. Update this file: tick the task, append one line to **Loop log**, set
   **Current focus**. If a milestone's tasks are all ticked, tick the milestone.
7. Engine bug found? Append to `../../../ENGINE-ISSUES-for-ubpa.md` — never patch
   the engine. (Per local CLAUDE.md: build on the engine, no out-of-engine impl.)
